# Wheel-Leg Controller 控制节点说明

## 1. 项目概述
本包（`wheel_leg_controller`）是一个基于 ROS 2 的独立控制节点，用于接管 MuJoCo 轮足机器人仿真。通过订阅传感器数据并运行 VMC（虚拟模型控制）与 LQR（线性二次型调节器）算法，实现对轮足机器人的平衡控制与速度追踪。

## 2. 控制结构与数据流
本节点严格遵循 ROS 2 的解耦架构，仅通过话题（Topic）与仿真器通信，不包含任何物理引擎代码（如 MuJoCo）。
- **输入 (订阅)**：
  - `/imu` (`sensor_msgs/msg/Imu`)：获取机体的 Pitch、Roll 姿态四元数及角速度。
  - `/joint_states` (`sensor_msgs/msg/JointState`)：获取左右腿（近端/远端）及车轮电机的实时位置与速度。
  - `/cmd_vel` (`geometry_msgs/msg/Twist`)：接收外部遥控指令。
- **输出 (发布)**：
  - `/actuator_cmd` (`rm_msgs/msg/WheelLegCmd`)：输出 6 个执行器的力矩指令（带硬性限幅保护）。
- **核心控制逻辑**：
  - **姿态解算**：将四元数转换为欧拉角（Pitch/Roll），用于后续反馈。
  - **腿部 VMC 控制**：结合 `vmc_cal.py` 的正运动学，将关节角转化为虚拟腿长 \(L_0\) 与摆角 \(\theta\)。
  - **LQR 平衡**：基于当前腿长通过多项式实时计算 K 矩阵，结合 12 维状态向量计算髋关节力矩 \(T_p\) 与轮毂力矩 \(T_w\)。
  - **横滚补偿 (Roll PID)**：通过横滚角偏差动态调整左右腿长，抵抗侧翻。
  - **速度平滑追踪**：引入 `accel_rate` 限制加速度，防止急加速/急刹车导致的惯性失稳。

## 3. K 矩阵与参数来源
- **运动学与动力学参数**：复用队内已有的数学库，将 `vmc_cal.py` 等直接封装进本包。
- **LQR K 矩阵**：调用 `lqr_update.py` 中的多项式拟合函数，根据实时腿长动态生成 12x1 的反馈增益矩阵。
- **PID 参数（调参记录）**：
  - 腿部支撑力 PID：`Kp=300.0`, `Kd=20.0`（下调了比例增益以模拟物理弹簧，吸收震荡）。
  - 速度平滑系数：`accel_rate = 0.3`（起步与倒车更加丝滑）。
  - 横滚 PID：`roll_kp=0.15`, `roll_kd=0.01`。

## 4. 测试现象与局限性分析（如实记录）

在仿真测试中，我们遇到了以下现象并进行了记录与修复：

1. **初始运动方向反转及解决**：
   - **现象**：节点启动后，机器人向后移动。
   - **解决**：经排查，这是 MuJoCo 物理引擎模型轮毂电机极性与 ROS 2 标准坐标系定义相反导致的。在 C 端（终端 `cmd_vel` 控制端）将 `linear.x` 的符号取正（发送 `x: 0.1`）后，机器人恢复正常的向前行驶，且能保持平稳。

2. **下台阶失稳摔倒（已知局限）**：
   - **现象**：在尝试跨越地形（下台阶）时，机器人底盘会磕碰台阶边缘，随后发生侧翻或前后栽倒。栽倒原因与加速度，速度，重心平衡有关，暂时未解决
   - **原因分析**：
     - **惯性突变**：下台阶瞬间，LQR 控制器依据 IMU 的 Pitch 突变给出巨大的轮毂力矩，但由于此时前轮悬空，巨大的反作用力直接掀翻了车体。
     - **缺乏落地缓冲**：VMC 的腿部支撑力在碰撞瞬间表现得过于“刚硬”，无法吸收地形突变带来的冲击。
   - **后续改进方向**：需要引入 `ground_detection`（离地检测）节点，在轮子悬空瞬间切断力矩输出，并利用接触力估计实现类似“弹簧阻尼”的动态落地缓冲。

## 5. 实测数据记录
- **实测平衡时长**：> 60 秒（在平地上，无外力干扰下可长时间保持直立）。
- **Pitch 曲线特征**：起步加速时 Pitch 会有约 -0.05 rad 的前倾，0.5秒内恢复；急刹车时由于惯性会有短暂俯仰震荡
